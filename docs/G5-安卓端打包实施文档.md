# G5 安卓端打包与适配实施文档

> 目标：把 Watermark Tool（抖音 / X 解析下载）打包为可安装运行的 Android APK。
> 状态：G1-G4（Go 迁移）已完成，G5（安卓端）**尚未开始**。
> 文档日期：2026-08-09
> 当前基线：v0.3.5（Tauri 2 + Vue3 + Go 后端）

---

## 1. 目标与范围

**G5 目标**：生成一个可在 Android 设备上安装、运行的 APK，具备抖音 / X 解析、播放、下载能力（能力与桌面端对齐，受平台限制的部分明确降级）。

**范围**：
- [ ] 后端在 Android 上的运行方案（核心难点）
- [ ] 前端（Vue3）在 Tauri 2 Android WebView 中运行
- [ ] APK 构建流程跑通（debug / release）
- [ ] 安装与实机验证
- [ ] 发布产物（release APK）

**明确不包含（本里程碑）**：App Store / 应用商店上架、签名证书正式签发、多 ABI 优化。

## 2. 当前架构与 Android 的差异

### 2.1 桌面端/网页端现状

```
Vue3 前端 ──HTTP(127.0.0.1:17890)──> Go 后端(wm-backend.exe)
                                      ├─ 抖音: chromedp + 系统 Edge（捕获页面签名请求重放）
                                      └─ X   : 纯 HTTP（vxtwitter/fxtwitter/GraphQL）
```

### 2.2 Android 平台差异（打包前必须认清）

| 组件 | Windows | Android | 影响 |
|---|---|---|---|
| Go 后端（wm-backend.exe） | 原生运行 | **PE 格式无法执行** | 需交叉编译或改架构 |
| 抖音解析浏览器 | 系统 Edge（chromedp 驱动） | **无系统 Edge，chromedp 不可用** | **核心难点** |
| X 解析 | 纯 HTTP | 纯 HTTP（可交叉编译） | ✅ 可工作 |
| 本地媒体代理 | 后端内建 | 后端内建 | 随后端 |
| 前端（Vue3 + WebView） | Tauri WebView2 | Tauri Android WebView | ✅ 可复用 |

**结论：安卓端不能直接复用 Windows 后端的抖音链路，必须先确定后端方案。**

## 3. 后端方案选型（G5 第一步，需评审决策）

### 3.1 候选方案对比

| 方案 | 抖音可行性 | X 可行性 | 成本 | 说明 |
|---|---|---|---|---|
| **A. 远端后端模式**（推荐） | ✅ 完整 | ✅ | 低 | 安卓 App 作前端，连接局域网/远程运行 Go 后端的机器（PC/服务器） |
| B. Go 后端交叉编译 android + 内置浏览器内核 | ❌ 无可用驱动浏览器 | ✅ | 高 | Android 无系统 Chrome/Edge 可被 chromedp 启动；内置 Chromium（1-2GB）难以作为系统浏览器暴露调试端口 |
| C. Android WebView 内嵌 + CDP 捕获 | ⚠️ 需自研 WebView 调试桥 | ✅ | 高 | Android System WebView 支持 `--remote-debugging-port`，但应用内嵌 WebView 暴露调试端口的方案不成熟 |
| D. 抖音改纯 HTTP（a_bogus 签名） | ⚠️ 签名逆向成本高、易失效 | ✅ | 高 | 违背"复用页面签名"的现有策略，维护成本大 |

### 3.2 推荐：方案 A（远端后端模式）

**架构**：
```
Android App(Vue3 + Tauri WebView)
      │  HTTP(可配置后端地址，如 http://192.168.1.5:17890 或云端)
      ▼
Go 后端（运行在 PC/服务器，复用现有 wm-backend.exe 完整能力）
```

**理由**：
- **零后端改动**：完整复用现有 Go 后端（抖音 CDP 链路 + X 链路 + 媒体代理 + 任务队列）
- 安卓端仅需：前端增加"后端地址配置"（默认 `http://10.0.2.2:17890` 模拟器 / 可填局域网 IP）
- 先跑通打包与安装验证，后端方案再逐步演进
- 缺点：解析/下载依赖后端所在机器的可达性（同局域网或公网部署）

**演进路径**：方案 A 跑通后，可再评估 B/C/D 做"纯本机"能力，作为 G5.1/G5.2。

## 4. 环境准备（首次打包必装）

### 4.1 依赖清单

| 依赖 | 版本要求 | 安装方式 | 说明 |
|---|---|---|---|
| Rust | stable | 已装（需加安卓 target） | `rustup target add aarch64-linux-android armv7-linuxandroideabi x86_64-linux-android` |
| JDK | 17+（本机 21 ✓） | 已装 | Gradle 兼容 |
| Android SDK | platform-tools + platforms;android-35 + build-tools;35.x | **未装，需下载** | 设置 `ANDROID_HOME` |
| Android NDK | 27.x | **未装，需下载** | Rust→so 链接必需 |
| Gradle | 由 Tauri CLI 自动管理 | 自动 | |
| @tauri-apps/cli | 2.x（本机 2.11.4 ✓） | 已装 | |

### 4.2 Android SDK 安装步骤（未装环境时执行）

```powershell
# 1. 下载 commandlinetools（约 150MB）
#    https://developer.android.com/studio#command-line-tools-only
#    解压到 C:\Android\cmdline-tools\latest

# 2. 设置环境变量（用户级）
$env:ANDROID_HOME = "C:\Android"
$env:ANDROID_SDK_ROOT = "C:\Android"   # 二者都设，Tauri 读取
#   并加入 PATH：C:\Android\cmdline-tools\latest\bin

# 3. 用 sdkmanager 安装组件（共约 2-3GB）
sdkmanager "platform-tools" "platforms;android-35" "build-tools;35.0.0" "ndk;27.2.12479018"

# 4. 验证
adb --version
sdkmanager --list_installed
```

### 4.3 Rust 安卓 target

```powershell
rustup target add aarch64-linux-android armv7-linux-androideabi x86_64-linux-android
rustup target list --installed   # 确认
```

## 5. 前端与 Tauri 配置适配

### 5.1 后端地址可配置（方案 A 必需）

- 前端 API 基地址从硬编码 `http://127.0.0.1:17890` 改为**可配置**：
  - 默认：桌面端/网页端保持 `127.0.0.1:17890`
  - 安卓：默认 `http://10.0.2.2:17890`（模拟器映射宿主机）；真机填局域网 IP
  - 设置抽屉新增"后端地址"输入项，持久化到 localStorage
- 涉及文件：`desktop/src/api/client.ts`（API 基地址）、`desktop/src/views/HomeView.vue`（设置项）

### 5.2 Tauri 安卓配置

- `desktop/src-tauri/tauri.conf.json`：
  - `bundle.android` 无需多余配置（已有 `debugApplicationIdSuffix`）
  - `identifier`：`com.watermark.tool`（已存在）
- 权限：安卓端仅需 `INTERNET`（Tauri 默认带）；下载文件需 `WRITE_EXTERNAL_STORAGE`（Android 10+ 用分区存储，一般无需）

### 5.3 资源

- 图标：`icons/` 已有 32/128/icns/ico；安卓需要 `mipmap`（Tauri android init 会自动从 icon 生成）
- sidecar：方案 A 下**不需要**把 wm-backend.exe 打进 APK（后端在远端）

## 6. 打包流程（Tauri 2 Android）

### 6.1 初始化（首次）

```powershell
cd desktop
npm run tauri android init
# 生成 src-tauri/android/ 目录（Gradle 工程）
```

### 6.2 构建 Debug APK（验证用）

```powershell
npm run tauri android build -- --debug
# 产物：src-tauri/android/app/build/outputs/apk/debug/app-debug.apk
```

### 6.3 构建 Release APK（发布用）

```powershell
npm run tauri android build
# 产物：src-tauri/android/app/build/outputs/apk/release/app-release.apk
# 签名：默认 debug 签名；正式发布需配置签名（见 7.3）
```

### 6.4 指定 ABI（可选，加快构建）

```powershell
npm run tauri android build -- --target aarch64   # 仅 arm64（主流真机）
```

### 6.5 常见错误

| 错误 | 原因 | 解决 |
|---|---|---|
| `Android SDK not found` | ANDROID_HOME 未设置 | 按 4.2 配置 |
| `NDK not found` | 未装 NDK | `sdkmanager "ndk;27.x"` |
| Rust target 缺失 | 未 add target | 按 4.3 |
| `licenses not accepted` | SDK 许可未接受 | `sdkmanager --licenses` |

## 9. 风险与决策点

| 风险 | 影响 | 缓解 |
|---|---|---|
| 抖音在安卓本机无法解析（无浏览器内核） | 方案 A 下依赖远端后端 | 文档明确依赖；后续评估 B/C |
| 局域网后端可用性 | 异地无法使用 | 后续支持公网部署后端 |
| SDK/NDK 下载体积与网络 | 首次打包慢 | 分批下载、镜像源 |
| 前端地址配置改动影响桌面端 | 回归风险 | 默认值保持 127.0.0.1:17890，改动最小化 |
